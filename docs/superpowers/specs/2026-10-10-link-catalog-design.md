# GTFS Visualizer — Link Catalog (replaces the R2 mirror)

**Date:** 2026-10-10
**Status:** Approved design, pending implementation plan
**Scope:** Replace the nightly R2 mirror with a catalog of links built from Mobility Database plus a small curated list; let users import directly, with their own API key, or by downloading and uploading a file.

## 1. Purpose

The mirror re-hosts feed zips on R2, which costs infrastructure, needs a scheduled job and secrets, and re-distributes data whose license the author doesn't control. A catalog of links avoids all of that. Mobility Database (MobilityData) already lists ~2,840 active GTFS feeds with access metadata and hosts CORS-enabled copies of most of them, so most feeds become directly importable in the browser.

The app is not deployed; no migration of existing users is needed.

## 2. Findings that shaped the design (checked 2026-10-09/10)

| Source | Browser fetch from a web origin |
|---|---|
| `https://cdn.mbta.com/MBTA_GTFS.zip` | Blocked (no CORS headers) |
| `https://gtfs.remix.com/oswego_county_us.zip` (S3) | Blocked (no CORS; preflight 403) |
| ODPT Tokyo Metro, with `acl:consumerKey` | OK (302 → Azure Blob, both `Access-Control-Allow-Origin: *`) |
| `https://files.mobilitydatabase.org/mdb-437/latest.zip` (MBTA) | OK, 24.6 MB |
| `https://files.mobilitydatabase.org/mdb-3520/latest.zip` (Oswego) | OK, identical bytes to source |
| `https://files.mobilitydatabase.org/feeds_v2.csv` | OK, 2.7 MB |
| Transitland REST API without a key | 401 |

- `feeds_v2.csv` columns used: `id`, `data_type`, `status`, `provider`, `name`, `location.country_code`, `location.subdivision_name`, `location.municipality`, `urls.direct_download`, `urls.authentication_type` (0 none, 1 API key in query, 2 API key in header), `urls.authentication_info` (signup URL), `urls.api_key_parameter_name`, `urls.latest`, `urls.license`, `location.bounding_box.*`.
- Ids are opaque strings with several prefixes (`mdb-`, `tdg-`, `tld-`, `jbda-`, …).
- 590 active GTFS feeds have non-Latin names (581 Japanese); for those, `provider`/`name` are Japanese and `municipality`/`subdivision_name` are English.
- Tokyo Metro's keyed feed is not in Mobility Database.
- Hosted copies send `ETag` and `Last-Modified`.

**Terms (mobilitydatabase.org/terms-and-conditions):** metadata generated by MobilityData is CC0 1.0; feed contents stay under each data owner's license and users are responsible for compliance; no availability guarantee; terms may change without notice. Therefore: show each feed's license, treat hosted copies as a convenience with a fallback, and avoid per-visitor catalog downloads.

## 3. Decisions

| Topic | Decision |
|---|---|
| Catalog source | Hybrid: Mobility Database for discovery and hosted downloads + curated `catalog/catalog.json` for featured feeds and feeds Mobility Database lacks |
| Access kind | Declared per entry (`direct` / `key` / `download`), derived from Mobility Database columns or set in the curated file; runtime fallback to download instructions when a direct fetch is blocked |
| Delivery of the catalog | Build-time snapshot (`npm run catalog:sync`), shipped as `public/catalog.json`; committed snapshot used when Mobility Database is unreachable |
| API keys | The visitor's own, stored in `localStorage` per provider, passed with each import/check; "Forget key" |
| Update detection | `HEAD` against the entry URL, compare stored `ETag` / `Last-Modified` |
| Finding feeds | Featured list + text search with access badges |
| Mirror pipeline | Removed (not deployed, no migration) |

## 4. Catalog data and snapshot

### Curated file `catalog/catalog.json`

An array of featured entries, either a reference or a full entry:

```json
[
  {"mdbId": "mdb-437"},
  {
    "id": "tokyo-metro",
    "name": "Tokyo Metro",
    "place": "Tokyo, Japan",
    "url": "https://api.odpt.org/api/v4/files/TokyoMetro/data/TokyoMetro-Train-GTFS.zip",
    "access": {"kind": "key", "provider": "odpt", "signupUrl": "https://developer.odpt.org/", "queryParam": "acl:consumerKey"},
    "license": "https://developer.odpt.org/terms/data_basic_license.html"
  }
]
```

- A reference (`mdbId`) takes every field from Mobility Database; any field given alongside it overrides.
- A full entry requires `id` (`/^[a-z0-9][a-z0-9-]{0,63}$/`), `name`, `place`, `url`, `access`; `originalUrl`, `license`, `bbox` are optional. `id` must not collide with a Mobility Database id.
- `access` is one of:
  - `{"kind": "direct"}`
  - `{"kind": "key", "provider": string, "signupUrl": string, "queryParam": string}` or the same with `"header": string` instead of `queryParam` (exactly one)
  - `{"kind": "download", "pageUrl"?: string}`
- Validation errors fail the build with a message naming the entry index and field.

### Entry shape (`CatalogEntry`, in `src/catalog/catalog-types.ts`, dependency-free)

`{id, name, place, url, originalUrl: string | null, access, license: string | null, bbox: [minLon, minLat, maxLon, maxLat] | null, featured: boolean, viaMobilityDatabase: boolean}`

### Mapping a Mobility Database row

Keep rows with `data_type = gtfs` and `status` in `active` or empty.

- `name`: `name` if non-empty, else `provider`; when both exist and differ, `"<provider> — <name>"`.
- `place`: non-empty of `municipality`, `subdivision_name`, `country_code`, joined with `", "`.
- `originalUrl`: `urls.direct_download` (or null).
- `license`: `urls.license` (or null). `bbox` from the bounding box columns when all four parse.
- `access` and `url`:
  - `authentication_type` 1 → `{kind: 'key', provider: <host of direct_download>, signupUrl: authentication_info, queryParam: api_key_parameter_name}`, `url = direct_download`, `viaMobilityDatabase = false`.
  - `authentication_type` 2 → same with `header` instead of `queryParam`.
  - otherwise, with `urls.latest` → `{kind: 'direct'}`, `url = urls.latest`, `viaMobilityDatabase = true`.
  - otherwise → `{kind: 'download', pageUrl: null}`, `url = direct_download`, `viaMobilityDatabase = false`.
  - Key rows missing a signup URL or parameter name fall back to `download`.

### `npm run catalog:sync` (`scripts/catalog/sync.ts`)

1. Download `https://files.mobilitydatabase.org/feeds_v2.csv` (timeout 60 s).
2. Map rows as above; on download failure, read `catalog/mdb-snapshot.json` (the mapped entries) and print a warning.
3. Merge curated entries (`featured: true`; references resolved and overridden; unknown `mdbId` fails the build).
4. Write `public/catalog.json` = `{generatedAt, entries}` (featured first in file order, then the rest sorted by `name`). `public/catalog.json` is git-ignored.
5. `--update-snapshot` also rewrites `catalog/mdb-snapshot.json`.

`npm run build` runs `catalog:sync` before `tsc -b && vite build`. `npm run dev` runs it once if `public/catalog.json` is missing. The CSV parser lives in the script (RFC 4180 quoting; no new dependency).

## 5. Getting a feed

### Keys

`src/catalog/key-store.ts`: `getKey(provider): string | null`, `setKey(provider, key): void`, `forgetKey(provider): void`, all wrapped in try/catch (storage may be unavailable), stored under `gtfs-visualizer:key:<provider>`.

### Import request

`ImportSource` gains `{kind: 'catalog', entry: CatalogEntry, key: string | null}` replacing the old catalog variant. The worker:

- builds the request: `key` access adds `?<queryParam>=<key>` (URL-encoded, preserving existing query) or the `<header>: <key>` request header;
- stores on the feed record: `sourceKind 'catalog'`, `sourceRef = entry.id`, `name = entry.name`, plus `license`, `viaMobilityDatabase`, `source_etag`, `source_last_modified` (§6);
- never includes the key in messages, issues or logs: every URL shown is reduced to origin + path.

New `ImportFailure` codes:
- `key_rejected` — HTTP 401/403 on a `key` entry: "The provider rejected this key."
- `blocked` — fetch throws (network/CORS) on a `direct` or `key` entry: the UI shows the download instructions for that entry.

### Picker behavior by access kind

| Kind | Before import | Action | On failure |
|---|---|---|---|
| `direct` | "Import" | worker fetches `url` | `blocked` → download instructions (link `originalUrl`); HTTP errors as today |
| `key` | no saved key → signup link, key field, "Save key and import"; saved key → "Import" + "Forget key for <provider>" | worker fetches with key | `key_rejected` → message + key field reopened; `blocked` → download instructions |
| `download` | "Download <name>" link (`pageUrl ?? originalUrl ?? url`, new tab) + "Upload downloaded file for <name>" file input | the uploaded file is imported as this catalog entry | as uploads today |

An uploaded file for a catalog entry uses `ImportSource {kind: 'catalog-file', entry, file}`: catalog identity, no validators.

## 6. Update checks

- At import the worker saves the final response's `ETag` and `Last-Modified` into new `meta.db` columns `source_etag`, `source_last_modified`, plus `license` and `via_mdb`. `FeedService.init()` adds missing columns (checked via `PRAGMA table_info`). `catalog_sha256` stays unused. `FeedRecord` replaces `catalogSha256` with `sourceEtag`, `sourceLastModified`, `license`, `viaMobilityDatabase`.
- `src/catalog/update-check.ts`: `checkForUpdate(entry: CatalogEntry, record: FeedRecord, key: string | null, fetchFn): Promise<'update' | 'current' | 'unknown'>`:
  - `unknown` when the record has no validators, access is `download`, or access is `key` without a key;
  - otherwise `HEAD url` (key added as in §5); compare ETags ignoring a leading `W/` when both exist, else `Last-Modified`; network error, non-2xx, or neither header → `unknown`.
- Runs in the UI when the feed list opens, for saved catalog feeds whose entry is in the snapshot; at most 4 concurrent; cached per session. `update` → "Update available" + re-import button.

## 7. UI

### Picker

1. "Featured" list.
2. Search box `aria-label="Search feeds"`, debounced 150 ms; up to 50 results, then "Showing 50 of N — refine your search".
3. Each row: name, place, access badge ("Direct", "Key required", "Download manually"), and the §5 actions; key and download rows expand in place.

The snapshot is fetched once from `/catalog.json`. On failure: "The catalog is unavailable right now." — URL import and upload stay usable.

### Search (`src/catalog/search.ts`)

- Normalize query and fields: NFKC → lowercase → NFD, remove U+0300–U+036F → NFC → katakana (U+30A1–U+30F6) mapped to hiragana (−0x60).
- Query split on whitespace (including U+3000); every token must be a substring of some field (`name`, `place`, `id`).
- Rank: entries where every token matches `name` first, then the rest; ties keep catalog order.
- No romanization and no simplified/traditional Chinese folding.

### Feed details

For catalog feeds: "Data: <agency> · License" (link when `license` is set) and "via Mobility Database" when `viaMobilityDatabase`. Read from the feed record, so it survives the entry leaving the catalog.

### Accessible names (E2E depends on them)

"Search feeds" (searchbox); buttons "Import <name>", "Save key and import <name>", "Forget key for <provider>"; link "Download <name>"; file input "Upload downloaded file for <name>".

## 8. Removed

`scripts/mirror/` and tests; `.github/workflows/mirror-catalog.yml`; `npm run mirror`; `@aws-sdk/client-s3`; `catalog.lock.json` handling, `CatalogLock`, `parseLock`, `feedZipKey`, `LOCK_FILE`; checksum logic in `src/catalog/catalog.ts`; `VITE_CATALOG_BASE_URL` (code, `.env.e2e`, docs). `docs/deploy.md` drops R2 and GitHub secrets and gains a "Catalog" section (featured entries, `catalog:sync`, `--update-snapshot`). CLAUDE.md's Catalog paragraph and commands are rewritten.

## 9. Error handling

Catalog load failure never blocks URL import or upload. Import failures stay in `ImportResult` (new `key_rejected`, `blocked`). Keys never appear in messages, issues, logs, or the app URL. Update checks fail silently to `unknown`. `catalog:sync` network failure → committed snapshot + warning; malformed curated entry → build failure naming the entry.

## 10. Testing

- Unit: CSV parsing (quoted fields, commas, newlines in quotes); row mapping (three access kinds, auth fallbacks, inactive/non-GTFS dropped, name/place composition, bbox); curated validation and merge (references, overrides, unknown `mdbId`, id collision); key store (unavailable storage); worker request building (query param appended to an existing query, header) and URL redaction; `checkForUpdate` (ETag, weak ETag, Last-Modified, none, HEAD failure, missing key, download access); search (Latin accents, full-width, kana equivalence, CJK substrings, U+3000 split, ranking, 50-result cap); `meta.db` column migration.
- E2E (catalog faked with `context.route`): direct import; key flow (save key → import → reload shows "Forget key for <provider>"); blocked direct import → download instructions → upload file → saved under the catalog name; search finds a Japanese feed by Japanese name and by English place; "Update available" when the faked `HEAD` returns a new ETag.
